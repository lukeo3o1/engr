01a049b3-62 §1   open    engr exists to preserve settled engineering knowledge across long-running work: decisions, rationale, invariants, and trust boundaries that ordinary diffs and project-management metadata do not retain.
01a049b3-62 §2   open    The record stays deliberately small. Unsettled plans, progress, conversation, and speculative structure are not durable authority; the model grows only after real recorded use demonstrates that a missing concept costs more than adding it.
01a049b3-63 §1   open    Nothing enters the engineering record unless a human has read and confirmed the exact proposed change. Every semantic action follows prepare, review of the rendered change, and confirm with the exact challenge phrase.
01a049b3-63 §2   open    Preparation validates and freezes the mutation before review. A candidate records its expected object revision; a later state change makes it stale, and preparing another candidate for the same object supersedes the earlier challenge.
01a049b3-65 §1   open    An Object is the durable knowledge aggregate and holds coherent Sections. Each Section contains the current confirmed wording; there is no competing current-text field and no stored staleness verdict.
01a049b3-65 §2   open    Object identifiers are UUIDv7 and resolve by unique prefix. Section identifiers are monotonic integers scoped to an Object, never reused or renumbered, so deletion cannot silently retarget an external reference.
01a049b3-67 §1   open    Every Section records the committed Git basis against which its wording was admitted. Basis movement is computed at read time and reported as information rather than an automatic semantic verdict.
01a049b3-67 §2   open    A Section reference pins the target Section hash and Git commit. Reads distinguish a moved basis from a changed dependency, and the recorded commit permits recovery of the earlier target wording.
01a049b3-6a §1   open    Sections are current authority. Confirmed events are projected immediately and serve only as a purgeable buffer in this historical generation; committed Git projections provide durable look-back.
01a049b3-6a §2   open    Projection is deterministic: the reducer depends only on the prior Object and admitted event, never clocks, Git queries, model calls, or interpretation of prose. Writer serialization and atomic replacement prevent partial authoritative states.
